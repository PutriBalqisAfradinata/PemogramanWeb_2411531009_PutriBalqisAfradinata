Pada praktikum ini, pengaturan disimpan dengan SharedPreferencesAsync, sedangkan resep favorit dan catatan disimpan di SQLite agar tetap tersedia setelah aplikasi dibuka kembali.

I. Tujuan Praktikum

  1. Menyimpan dan membaca mode gelap serta pilihan tampilan grid.
  2. Menerapkan Create, Read, Update, dan Delete pada data favorit dengan SQLite.
  3. Menambahkan catatan pribadi melalui migrasi tabel tanpa menghapus data favorit lama.
  4. Menguji provider dan operasi database tanpa bergantung pada emulator atau internet.

II. Dasar Teori

2.1 SharedPreferencesAsync

Penyimpanan key-value untuk nilai pengaturan sederhana seperti boolean dan String. Operasinya asynchronous; key yang belum tersimpan menghasilkan null sehingga aplikasi dapat memakai nilai default.

2.2 SQLite dan sqflite

SQLite menyimpan data terstruktur dalam database lokal. sqflite menyediakan query, insert, update, dan delete. Data query dipisahkan melalui whereArgs agar nilai tidak disisipkan langsung ke string SQL.

2.3 Migrasi database

Nomor version menandai struktur database. Saat versi aplikasi lebih tinggi daripada database yang sudah ada, onUpgrade menambah kolom baru sambil mempertahankan baris lama. DEFAULT memberi nilai awal untuk data yang sudah tersimpan.

2.4 Provider dan FavoriteStore

Widget berkomunikasi dengan provider, sementara provider menggunakan kontrak FavoriteStore. Implementasi SQLite dipakai aplikasi dan penyimpanan memori dipakai widget test, sehingga logika UI dapat diuji tanpa database perangkat.

III. Alat dan Bahan

  • Flutter SDK, Visual Studio Code/Android Studio, dan emulator Android.
  • Project ResepKu serta koneksi internet untuk memuat resep API.
  • Package shared_preferences, sqflite, dan path.
  • Package pengujian sqflite_common_ffi dan shared_preferences_platform_interface.

Database favorit disimpan lokal; halaman resep dari API tetap memerlukan internet.

IV. Langkah-Langkah Praktikum

Bagian A — Pengaturan dengan SharedPreferencesAsync
4.1 Langkah A.1 — Memasang package

Package SharedPreferencesAsync dipakai untuk menyimpan mode gelap dan grid. sqflite dan path disiapkan untuk penyimpanan favorit pada Bagian B; package test dipakai dalam pengujian.

4.2 Langkah A.2 — Membuat SettingsProvider

SettingsProvider memuat pengaturan sebelum aplikasi dibangun dan menyimpan perubahan setelah memberi tahu listener. Nilai default yang dipakai adalah tema terang dan tampilan list.

4.3 Langkah A.3 — Memuat data sebelum runApp

Fungsi main menginisialisasi binding, memuat pengaturan dan favorit, lalu mendaftarkan provider sebelum runApp. ThemeMode memilih tema terang atau gelap dari nilai tersimpan.

4.4 Langkah A.4 — Menghubungkan grid dan halaman Pengaturan

Home membaca nilai grid dari SettingsProvider. Switch di halaman Pengaturan mengubah tema dan layout; notifikasi provider membangun ulang widget terkait.

Checkpoint 1 — Pengaturan bertahan setelah dibuka ulang

Mode gelap dan tampilan grid diaktifkan. Setelah aplikasi ditutup dan dibuka lagi, Home tetap memakai tema gelap dan layout grid. Footer identitas terlihat pada kedua screenshot.

Bagian B — Favorit tersimpan di SQLite
4.5 Langkah B.1 — Menyiapkan data resep untuk disimpan

Method Recipe.toJson() mengubah objek menjadi Map JSON. Kolom data pada tabel favorit menyimpan serialisasi resep agar bahan dan instruksi bisa dimuat lagi.

4.6 Langkah B.2 — Model Favorite

Model Favorite membungkus Recipe dengan waktu penyimpanan, catatan, dan jumlah resep dimasak. toMap dan fromMap menjadi jembatan objek dan baris SQLite.

4.7 Langkah B.3 — Membuat schema dan database

FavoriteDatabase membuka file database aplikasi, membuat tabel untuk instalasi baru, dan menjalankan migrasi kolom note serta cooked_count untuk database versi lebih lama. Versi schema dinaikkan secara berurutan.

4.8 Langkah B.4 — Operasi CRUD favorit

getAll membaca favorit terbaru lebih dulu, insert menyimpan atau mengganti id yang sama, sedangkan updateNote, incrementCooked, delete, dan deleteAll memperbarui data melalui query SQLite.

4.9 Langkah B.5 — FavoriteProvider dan pemuatan awal

Provider membaca baris database saat aplikasi dimulai. Saat favorit ditambah atau dihapus, state UI diperbarui dan perubahannya ditulis melalui FavoriteStore.

Checkpoint 2 — Favorit tetap ada setelah restart

Dua resep ditandai sebagai favorit, lalu aplikasi dibuka kembali. Badge tetap menunjukkan dua favorit dan halaman Favorit masih memuat kedua resep.

Bagian C — Catatan pribadi dan migrasi
4.10 Langkah C.1 — Menyimpan catatan pada Favorite

Field note disimpan sebagai kolom tersendiri. copyWith membuat objek baru saat catatan berubah, sementara nilai kosong menjadi default untuk baris lama.

4.11 Langkah C.2 — Migrasi database versi 1 ke versi 2

onUpgrade menambahkan kolom note dengan nilai awal kosong. Database yang sudah memiliki favorit tidak perlu dihapus; data lama tetap tersedia.

4.12 Langkah C.3 — Menulis perubahan catatan

FavoriteProvider mengganti objek dalam state, memberi notifikasi, lalu menyimpan catatan melalui method updateNote pada kontrak FavoriteStore.

4.13 Langkah C.4 — Dialog catatan di halaman Favorit

Dialog menyediakan input catatan. Setelah Simpan ditekan, teks diteruskan ke provider; setelah aplikasi dibuka kembali, nilai yang tersimpan dimuat lagi dari SQLite.

Checkpoint 3 — Favorit lama dan catatan bertahan

Halaman Favorit tetap menampilkan data lama dengan nilai awal “Belum ada catatan”. Setelah catatan disimpan dan aplikasi dibuka ulang, teks catatan muncul kembali.

Bagian D — Pengujian
4.14 Langkah D.1–D.4 — Fake store, widget test, dan database test

MemoryFavoriteStore menggantikan SQLite saat test widget. SharedPreferences tiruan menguji pengaturan, sementara sqflite_common_ffi menjalankan test CRUD dan migrasi pada database komputer.

V. Latihan

Latihan 1 — Urutan favorit tersimpan

SettingsProvider menyimpan pilihan urutan sebagai String. FavoritePage mengurutkan salinan daftar agar list milik provider tidak berubah. Menu menyediakan urutan terbaru disimpan dan Nama A–Z.

Latihan 2 — Hapus semua favorit

Penghapusan menampilkan dialog konfirmasi sebelum menghapus semua baris. Setelah berhasil, provider memperbarui tampilan dan aplikasi menampilkan SnackBar.

Latihan 3 — Migrasi versi 3 (bonus)

Migrasi versi 3 menambahkan cooked_count dengan nilai awal nol. Tombol Sudah dimasak menaikkan jumlah secara atomik di SQLite, dan nilainya tetap ada setelah aplikasi dibuka kembali.

VI. Pertanyaan Analisis

1. Mengapa pengaturan memakai SharedPreferencesAsync dan favorit memakai SQLite?

Mode gelap, grid, dan urutan favorit adalah nilai kecil dengan key tertentu, sehingga SharedPreferencesAsync sesuai. Favorit berisi beberapa field dan perlu operasi CRUD serta relasi antar kolom, sehingga lebih sesuai disimpan dalam tabel SQLite.

2. Apa kelebihan notifyListeners sebelum await setBool, dan risikonya?

UI berubah segera tanpa menunggu operasi disk sehingga terasa responsif. Jika penulisan gagal, tampilan sementara bisa berbeda dari nilai yang akan dibaca setelah restart; aplikasi dapat menangani error dan mengembalikan state bila diperlukan.

3. Apa akibat menambahkan note hanya di onCreate tanpa menaikkan version?

Database lama tidak menjalankan onCreate lagi, sehingga kolom note tidak terbentuk dan query update akan gagal. Meminta pengguna uninstall bukan migrasi yang aman karena dapat menghapus favorit yang sudah disimpan.

4. Apa keuntungan FavoriteStore bagi widget test?

FavoriteProvider bergantung pada kontrak FavoriteStore, bukan implementasi SQLite langsung. Test dapat memakai MemoryFavoriteStore untuk mengisi data dan memeriksa UI tanpa plugin native atau database perangkat.

5. Bagian mana yang tetap berfungsi dalam mode pesawat?

Pengaturan dan favorit tetap dapat dibaca karena tersimpan lokal di perangkat. Memuat atau mencari resep melalui DummyJSON memerlukan internet sehingga fitur tersebut tidak dapat mengambil data baru saat offline.

VII. Kesimpulan

ResepKu menyimpan pengaturan melalui SharedPreferencesAsync dan data favorit melalui SQLite. FavoriteStore memisahkan akses penyimpanan dari provider, sementara migrasi versi 2 dan 3 menambah catatan serta jumlah resep dimasak tanpa menghapus data lama. Pengujian otomatis yang dijalankan lulus seluruhnya, dan bukti layar checkpoint serta latihan disertakan dalam laporan.
